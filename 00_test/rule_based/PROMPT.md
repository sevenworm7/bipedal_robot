# 角色與目標
你是一位機器人控制工程師,任務是在 NVIDIA Isaac Sim / Isaac Lab 環境中,設計並實作一個
「rule-based(規則式/傳統控制法)」的雙足機器人行走控制器,作為後續 imitation learning + RL
訓練管線的初始教師策略(teacher policy)。此控制器不需要是最優步態,但必須能在多種情境下
穩定地讓機器人持續向前行走而不摔倒,以支援後續資料收集。

# 背景與限制
- 平台:Isaac Sim / Isaac Lab
- 目標機器人:[請填入具體型號與自由度數,例如:XX 人形機器人,雙腳各 N 個關節]
- 此控制器的輸入/輸出介面,必須與後續 RL/BC 訓練管線相容,定義如下(若與實際系統不同,
  請先向我確認並統一,兩邊不可各自為政):
  - 觀測 state:關節角度、關節角速度、base 姿態(quaternion/euler)、base 線速度與角速度、
    目標行走速度指令等
  - 動作 action:各關節目標角度(position control)或扭矩(torque control),需與後續 policy
    網路輸出格式一致

# 控制器設計需求
1. 選擇一個具體且可實作的規則式行走方法作為基礎(擇一或混合使用,並說明理由),例如:
   - 軌跡式步態(trajectory-based gait):以參數化擺動腳/支撐腳軌跡(如 Bezier 曲線或正弦
     函數)搭配逆向運動學(IK)轉換為關節角度目標
   - 簡化動力學模型平衡法:線性倒單擺模型(LIPM)+ Zero Moment Point(ZMP)或 Capture Point,
     計算落腳點以維持平衡
   - 分層式方法:高層決定步態相位與落腳點,底層用 PD 控制器追蹤關節軌跡目標
2. 需具備以下可調參數,以支援後續資料收集涵蓋多樣情境:
   - 步長(step length)
   - 抬腳高度(step height)
   - 步頻/步態週期(gait frequency / cycle time)
   - 目標行走方向與速度
3. 需包含基本的穩定性/平衡修正機制(即使簡單也要有),避免小擾動下立即跌倒,例如:
   - 依 base 傾斜角度微調關節目標
   - 依 COM 或 ZMP 偏移調整下一步落腳位置
4. 介面需封裝為單一可重複呼叫的類別,例如 `class RuleBasedBipedController`,提供:
   - `reset()`:重置內部狀態(相位、參考軌跡等)
   - `compute_action(observation) -> action`:輸入觀測,輸出當前時間步動作
   - 可在 Isaac Sim 模擬迴圈中逐步呼叫,產生連續動作序列

# 驗證與可靠度要求
1. 在 Isaac Sim 中對此控制器執行多組(建議至少 50~100 組)不同初始姿態、地形(若適用)、
   目標速度指令的評估 rollout,統計:
   - 平均行走距離(跌倒前)
   - 跌倒率(百分比)
   - 平均行走速度與方向誤差(相對指令)
2. 若跌倒率過高(建議先設門檻,例如超過 30%),需回頭調整參數或平衡邏輯,直到達到可接受
   的穩定度,才視為「堪用的教師策略」。
3. 錄製至少 3~5 段代表性評估影片,畫面疊加以下資訊(格式與後續 pipeline 的影片一致,方便
   日後直接比較進步幅度):
   - 步伐數、累積移動距離、經過時間、偏離直線距離、是否跌倒/結束狀態
