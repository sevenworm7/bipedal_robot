# Rule-based 控制器（實驗一，複製自 `02_rule_based/`）

完整需求在同資料夾的 `PROMPT.md`，動工前先讀完。實驗一的驗收標準與扭矩等決定見 `00_test/CLAUDE.md`，若和本檔不同，以 `00_test/CLAUDE.md` 為準。

本檔與 `PROMPT.md` 是 `02_rule_based/` 的複本，測試過程中可以依實際情況修改；原始版本保留在 `02_rule_based/` 不動，實驗一結束後再和使用者一起比較差異。

- 產出 `RuleBasedBipedController`（提供 `reset()` 與 `compute_action(obs) -> action`），作為訓練管線的教師策略。
- 控制器中所有和機器人相關的數值（腿長、關節順序、站姿、步態參數預設值）都從 `shared/robots/<robot>.py` 或 config 讀取，**不可寫死**；IK 以機器人的運動學參數計算。
- 觀測／動作空間從該實驗的 `shared/` import，不可在這裡另外定義（見根目錄 CLAUDE.md「跨流程介面契約」）。
- 可調參數（放在 config）：步長、抬腳高度、步頻／步態週期、目標方向與速度。
- 必須有平衡修正機制，例如依 base 傾角調整關節目標，或依 COM／capture point 調整落腳點。
- 驗收標準：評估 50–100 組 rollout（初始姿態、速度指令隨機化），跌倒率 < 30%；需統計平均行走距離、平均速度與方向誤差。
- 交付項目：程式碼＋config、統計報告、3–5 段評估影片（依 `/eval-video` 格式）、說明文件（觀測／動作定義、參數清單、已知限制）。
- 評估時使用大量平行環境（Isaac Lab vectorized env），不要逐一執行 rollout。
- 產出放在 `<產出根目錄>/rule_based/<run>/`（實驗一：`00_test/outputs/`；實驗二：`outputs/`）。

## 實作計畫（已和使用者確認，2026-09-18）
- **原則**：控制器只能使用 38 維觀測（2026-09-19 加入 `gait_freq`）與機器人的幾何常數（`shared/robots/ref_biped.py`），不可讀取模擬器的其他狀態，否則 BC 無法模仿。批次處理 N 個環境的 GPU tensor。
- **方法**：
  - 步態時序使用觀測中的步態相位（環境提供的時鐘），每個週期兩步。
  - 擺動腳：前後用平滑曲線，高度用 sin 曲線。支撐腳相對身體往後移。
  - 平面兩連桿 IK（大腿 0.10 m、小腿 0.09 m）算出髖 pitch 與膝，踝 pitch 讓腳掌保持平貼。
  - 用 hip roll 做和步態同步的側向搖擺（核心難點）。
  - 前 1–2 個週期逐漸加大步長與搖擺幅度。
- **平衡修正**：
  - 姿態回授：傾斜 → 修正髖 pitch / roll。
  - Raibert 式落腳點修正：依速度誤差與側向速度調整下一步。
  - 方向修正：沒有 hip yaw，只能用左右步長差輔助。
- **參數**：速度 = 2 × 步長 × 步頻。其他參數：抬腳高度、搖擺幅度、雙腳支撐比例、回授增益。可以設定每個 episode 隨機取值的範圍，增加資料多樣性。
- **開發步驟**：
  1. 離線驗證 IK
  2. 原地踏步（同時驗證步數計數）
  3. 固定參數往前走
  4. 加入回授，並用大量平行環境掃描參數
  5. 正式評估 100 個 episode，加上推擠測試（僅供參考）
  6. 錄 3–5 段影片（慢、中、快，以及失敗案例）、產出 `stats.json`、撰寫 README
- **執行結果（2026-09-19）**：步驟 4 的「參數掃描」最後採用 CEM（`optimize.py`），因為 19 個參數互相耦合，格點掃描找不到能前進的組合；側向搖擺實際上是讓兩腳一起翻到腳掌邊緣的「平行四邊形」擺動（見 README）。
- 成功率達不到 70% 時，帶著數據停下來和使用者討論，不可自行縮小指令範圍或放寬門檻。完成後先讓使用者檢視，再進入訓練階段。
