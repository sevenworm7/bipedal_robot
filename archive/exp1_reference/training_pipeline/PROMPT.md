# 角色與目標
你是一位機器人強化學習工程師,任務是在 NVIDIA Isaac Sim / Isaac Lab 環境中,實作一套
「rule-based controller 初始化 → behavior cloning → PPO 強化學習 → 自我蒸餾迭代」
的雙足機器人行走策略訓練管線,並產出附帶關鍵指標疊加資訊的評估影片,方便人工審查步態品質。

# 背景
- 模擬平台:NVIDIA Isaac Sim(搭配 Isaac Lab / Isaac Gym RL 框架)
- 深度學習框架:PyTorch
- RL 演算法:PPO(Proximal Policy Optimization)
- 策略網路:MLP
- 已有一個 rule-based 的雙足行走控制器,可作為初始教師策略

# 訓練管線需求(依序實作)

## 階段一:Rule-based controller → 資料收集
1. 在模擬環境中執行既有 rule-based 控制器,涵蓋多種初始姿態、地形、目標行走方向與速度指令的情境。
2. 收集每個時間步的 (觀測狀態 state, 控制器輸出動作 action) 配對,存成訓練資料集
   (建議 HDF5 或 npz,並記錄 episode 邊界)。
3. 資料規模與涵蓋範圍需足以支撐後續監督式學習,避免 overfit 到單一情境。

## 階段二:Behavior Cloning 訓練 MLP
1. 用階段一資料以監督式學習訓練 MLP policy,目標是模仿 rule-based controller 行為。
2. 明確定義:
   - state 維度與內容(關節角度/角速度、base 姿態、IMU、指令速度等)
   - action 維度與內容(關節目標角度或扭矩)
   - 網路架構(層數、寬度、激活函數)
   - loss function(建議 MSE 或 NLL)
   - 訓練/驗證切分方式
3. 輸出:可作為 PPO 初始化權重的 MLP checkpoint。

## 階段三:PPO 強化學習微調
1. 以階段二 MLP 權重初始化 PPO policy(actor,可選 critic)。
2. 在模擬環境中以 PPO 繼續訓練,獎勵函數至少包含以下項目並列出各項權重:
   - 前進速度 / 達成目標速度指令
   - 直線行走方向一致性(懲罰偏離直線/側向漂移)
   - 姿態穩定度(base 高度、姿態角、避免跌倒)
   - 能耗/扭矩懲罰
   - 步態自然度相關項(關節限制、接觸力規則化)
3. 訓練過程需記錄 reward curve、episode length、跌倒率等,用 tensorboard 或等效工具視覺化。

## 階段四:自我蒸餾(Self-Distillation)迭代循環
1. PPO 訓練完成後,對 policy 執行大量 rollout 評估。
2. 依明確篩選標準(例如:未跌倒、達成目標行走距離、側向偏移低於門檻、reward 前 X%)
   篩選出高品質 (state, action) 軌跡。
3. 用篩選資料重新以 behavior cloning 蒸餾出一個新 MLP。
4. 將新 MLP 作為下一輪 PPO 微調的初始化權重,重複「PPO 微調 → 篩選好資料 → BC 蒸餾」
   整個循環,共執行 3 輪迭代。
5. 每輪迭代保留 checkpoint、訓練 log、及該輪評估影片(見階段五),以利比較迭代間進步幅度。

## 階段五:評估影片產生 + 關鍵指標疊加顯示
每輪迭代訓練完成後的 policy(含最終策略),在模擬器中執行評估 rollout 並錄影,
畫面上需即時疊加以下資訊(固定位置如左上角或右上角,等寬字體、高對比色,
確保錄影解析度下仍清晰可讀):

- 目前步伐數(step count,即時計數)
- 累積移動距離(公尺,沿行走方向實際位移)
- 經過時間(格式如 00:00.00)
- 偏離直線距離(側向偏移量,公尺,可加簡易偏移軌跡線)
- 建議額外加入(若可行):迭代輪次/版本標籤、當下前進速度、跌倒/episode 結束狀態標記

技術要求:
- 每個 frame 都需更新對應數值,不可只顯示最終結果
- 數值需與模擬時間同步,不可有明顯延遲或跳動
- 輸出格式 mp4,至少 720p、30fps
- 檔名包含迭代輪次與時間戳記(例如 iter3_ppo_eval_20260917.mp4)

# 交付項目
1. 完整可執行訓練程式碼(階段一至四),含清楚的 config 管理超參數
2. 每輪迭代的模型 checkpoint 與訓練 log
3. 每輪迭代的評估影片(依階段五規格)
4. 簡短實驗結果總結,比較三輪迭代間步態品質、跌倒率、行走距離、直線度等指標變化
